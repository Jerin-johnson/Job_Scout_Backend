These are product comparisons, not evidence about internal systems. An implementation pattern commonly used for cross-source deduplication is deterministic identity first (source plus source ID), then a tracking-stripped canonical URL, then a conservative employer/title/location/date entity key. Content hashes detect changes. SimHash/MinHash or shingled similarity can flag candidates for review, but similarity alone is unsafe: two roles at the same employer can share most of their description. The approach here therefore never merges on embeddings or a description hash alone. The exact ATS-versus-aggregator canonical preference needs an audited cross-source match before consolidation. This is a design recommendation; large-scale engineering evidence for this repo is still pending.

## MongoDB findings and decisions

- Use unordered `bulkWrite` with bounded client batches and an identity unique index. MongoDB documents unordered writes as continuing after individual operation errors and the driver/server split large batches as needed ([bulk writes](https://www.mongodb.com/docs/manual/reference/method/db.collection.bulkWrite/)). Current app batch size is 500; benchmark rather than assuming larger is faster.
- Index only observed query shapes. Compound-index order determines which prefixes can serve a query; every index adds storage and write work ([compound indexes](https://www.mongodb.com/docs/manual/core/indexes/index-types/index-compound/create-compound-index/)). Use `explain("executionStats")` on representative data ([query optimization](https://www.mongodb.com/docs/v8.0/core/query-optimization/)).
- Partial indexes can reduce index size when a stable predicate (such as active records) is present in all relevant queries ([partial indexes](https://www.mongodb.com/docs/v8.0/core/index-partial/)). Existing indexes and actual Mongo deployment support must be checked before relying on them.
- WiredTiger supports Snappy, zlib and zstd collection compression. Compression saves disk at CPU cost; in-memory collection data is uncompressed, so disk compression is not a substitute for RAM sizing. The default for most collections is Snappy; zstd must be configured and measured on the actual deployment ([WiredTiger compression](https://www.mongodb.com/docs/manual/core/wiredtiger/)).
- Catalog reads use keyset cursor pagination and bounded projections. A count is cached/approximate, not a full `$facet` over every result. No Atlas Search or separate search service is assumed. MongoDB documents explain plans as the way to check index coverage and plans ([query optimization](https://www.mongodb.com/docs/v8.0/core/query-optimization/)).
- Keep description/detail and vector access separate from list queries. `job_details` and `job_vectors` are additive; old fields remain until an independently approved retirement.

## Local catalog visibility and storage measurements (historical 2026-10-17; see current verification below)

The local development database contains 747 active, unexpired records: 99 Remote OK, 640 Jobicy, 4 Remotive and 4 `mock_public_board` fixtures. The collection has 748 documents total (one is not active and unexpired). The normal user discovery query returned only **99 Remote OK** records. Jobicy's records are hidden because `ENABLE_JOBICY_INGESTION` defaults to `false`; setting it to `true` in a local backend environment exposes the 640 current Jobicy records (739 total through the approved/visible source registry; the 4 mock records are not a configured registry source). Jobicy remains opt-in and should not be enabled for production merely by setting the local flag. Remotive has 4 indexed rows but remains blocked because the registry has no written redistribution permission reference. `mock_public_board` is not in the source registry and is excluded from the public source list. Source policy enablement is not equivalent to actual reach on every user's eligibility-filtered Jobs view.

Jobicy's [current API guide](https://jobicy.com/jobs-rss-feed) documents the public keyless endpoint, cursor pagination up to 200 results per request, a roughly three-hour publication delay and a seven-day publication window. It asks integrators to attribute Jobicy and cache results appropriately; its guide says a few updates a day are usually sufficient and automated passes should not start more than once per hour. The current local flag preserves that hourly minimum interval and the adapter uses the canonical Jobicy listing URL. The paid commercial endpoint is not used. Remotive remains disabled pending written permission; the request text is in `docs/ai/18-job-source-policy.md`.

Read-only BSON sample from 100 of 748 local `jobs` documents: mean document size is 28,160 bytes with embedded legacy vectors and 7,664 bytes after excluding only vector fields. The sample's mean vector field alone is about 20,410 bytes. Collection stats report 21,866,287 logical bytes, 45,588,480 allocated bytes and 3,026,944 index bytes. A 2 KB target is **not met** by removing only `rawDescription`, `requirements`, `embedding` and `embeddingMetadata`: the remaining catalog projection still averages 7.7 KB. Reaching 2 KB would require moving additional scoring/provenance/eligibility fields and changing hot query code, with corresponding index and latency measurements. No fields were removed. The split dry run found all 748 jobs eligible for detail copies and all 748 for vector copies, but this only counts copy candidates; an independent content-by-content verification is required before any removal.

### New free-source coverage status

JobStream, NAV and France Travail now have fixture-tested adapters and remain disabled by default. No live yield figures are claimed. Terminal outbound network access is unavailable in this environment, so a polite full JobStream snapshot measurement and source refresh could not run. JobStream's public v2 service offers a JSONL snapshot and an updated-after event stream; the official dataset is CC0 ([dataset](https://data.arbetsformedlingen.se/dataservice/jobstream/), [v2 API](https://jobstream.api.jobtechdev.se/)). The adapter consumes JSONL incrementally, uses bounded batches and handles deletions. A conservative request budget remains configured pending real provider-side quota verification.

NAV's feed requires a bearer token, exposes active/inactive updates and requires consumers to remove inactive postings immediately; no local NAV credential is configured. Its API terms allow reuse when consumers deep-link to the original application function, but the token and deletion behavior need verification against fixtures before enabling ([feed documentation](https://navikt.github.io/pam-stilling-feed/), [terms](https://arbeidsplassen.nav.no/vilkar-api)).

France Travail's API is for active job offers, supports job-service use, and its public terms describe a reuse license for partners. It requires OAuth/API access and excludes contact data; because no credentials or accepted reuse license are present, it stays disabled. Exact retention and display requirements still need review with the license before any activation ([API overview](https://www.data.gouv.fr/dataservices/api-offres-demploi), [terms](https://www.francetravail.fr/informations/informations-legales-et-conditio/conditions-generales-dutilisatio.html)). Free deduplicated active reach and India-relevant share therefore remain unmeasured; existing indexed sources are heavily remote/global and must not be represented as complete global or Indian coverage.

## Scale and cost limits

`node scripts/benchmark-jobs-scale.js --sizes=100k,500k,1m` was run against local loopback MongoDB on 2026-10-16 with 1,000-op batches. Results: 100k at 5,493 ops/s, 2.66/10.30ms catalog p50/p95, 0.64/1.61ms candidate p50/p95, 9.58MB data and 8.45MB indexes; 500k at 6,308 ops/s, 9.16/30.06ms catalog, 0.64/1.39ms candidate, 60.5MB data and 45.7MB indexes; 1M at 6,303 ops/s, 12.83/50.19ms catalog, 0.49/1.05ms candidate, 122.2MB data and 87.8MB indexes. Recommended refresh was 58.28/273.71ms, 258.77/1,221.29ms, and 490.17/2,111.45ms respectively. An explain on the local 806-record catalog returned 400 candidates with 402 keys and 400 documents examined, using `job_candidate_recent_feed`, in 9ms. This benchmark uses compact synthetic documents and its RSS is the Node client, not MongoDB server RAM; see [scale-up measurements](jobs-scale.md) for caveats and BSON measurements from the local catalog. The benchmark's interrupted-run temporary collection was inspected and removed. A 1M production working-set RAM profile and hosting size remain **Unverified**.

Production monthly compute/storage cost is **Unverified** until host class, region, replica topology, backups and retention are known. This design has no per-job LLM or embeddings, so incremental AI/embedding API spend is $0; existing Mongo/Redis/worker costs are not zero and cannot be priced from repository code.

## Occupation quality status

The existing reproducible 100-title manually labeled check was rerun against the local catalog on 2026-10-16. It is a seeded sample of existing titles, not the requested independent stratified 300-job evaluation. Overall accuracy is 73/100 and 21/100 predictions are `unclassified`; the catalog-wide unclassified share is 155/806 (19.2%). Per-predicted-family precision was: accounting-finance 1/3 (33.3%), customer-support 8/9 (88.9%), data 1/1 (100%), design 5/5 (100%), education 1/1 (100%), healthcare 0/1 (0%), marketing 3/5 (60%), operations 8/9 (88.9%), product 1/1 (100%), sales 21/21 (100%), security 5/5 (100%), software 18/18 (100%), unclassified 1/21 (4.8%). Per-gold-family recall was: accounting-finance 1/1 (100%), customer-support 8/13 (61.5%), data 1/3 (33.3%), design 5/7 (71.4%), education 1/1 (100%), human-resources 0/1 (0%), marketing 3/5 (60%), operations 8/14 (57.1%), product 1/2 (50%), sales 21/23 (91.3%), security 5/6 (83.3%), software 18/23 (78.3%), unclassified 1/1 (100%). Source unclassified shares were mock public board 2/4 (50%), Remote OK 16/99 (16.2%), Remotive 1/4 (25%), Jobicy 136/699 (19.5%). Labels/sample size are too small and source-skewed for release claims; the requested independent 300-job stratified quality gate remains open and the <10% unclassified goal is not met.

Do not claim that 100k/500k/1M are supported until the benchmark runs and the actual explain plan and resource profile are reviewed. Tune batch size and worker concurrency from those measurements; avoid extra indexes that do not serve a measured query.

## Current local verification (2026-10-18)

The current loopback database has 618 active, unexpired documents: Jobicy 511, Remote OK 99, Remotive 4, and unregistered `mock_public_board` 4. Regular user discovery exposes 99 Remote OK jobs. Remotive's persisted registry row retains old `enabled/approved` booleans, but runtime policy blocks it until written redistribution permission exists. Jobicy's persisted row is disabled; local-only `ENABLE_JOBICY_INGESTION=true` is the single opt-in, and the current potential visible count is 610 (99 Remote OK + 511 Jobicy). The flag does not enable it in production. The catalog is an indexed set of approved source records, not the whole internet; each result includes source and posted-date labels.

Jobicy conditions implemented from its [current public API guide](https://jobicy.com/jobs-rss-feed): preserve Jobicy attribution and canonical listing URL; cache results; use the keyless public endpoint and its rolling seven-day feed (with a three-hour publication delay); cursor pages are capped at 200 and valid for 24 hours; automated starts must be at least one hour apart (registry budget 24/day). The guide says a few refreshes daily are normally sufficient. The adapter also implements its status endpoint in batches of at most 100; only an explicit `closed` response closes a listing. No paid ATS endpoint is used. Remotive remains blocked pending written permission; the request text remains in `docs/ai/18-job-source-policy.md`.

The 100-document BSON field-size sample remains 28,160 B mean including vectors, 7,664 B without vectors, and 20,410 B average vector storage. A full-catalog BSON dry run measured 29,247 B mean before proposed removals and 2,258 B mean after removing raw description, requirements, provenance and vectors (p95 2,881 B; max 3,604 B). Current index storage is 3,018,752 B. Compaction was not applied: the mean exceeds the 2,048 B target, and split-copy verification found no missing descriptions/requirements and no vector mismatches, but provenance differs on all 618 records because it was added to the detail split after the copies were made. No legacy data was deleted or overwritten. A provenance backfill and re-verification would be required before any later removal; removal would still miss the 2 KB target.

`npm run jobs:discovery:explain` returned 400 candidates, examining 402 index keys and 400 documents in 2 ms, using `job_candidate_recent_feed`. Adapter tests cover JobStream snapshot/event handling, NAV inactive-ad removal, and France Travail OAuth/active-offer mapping. Current France Travail terms state that API partners may reuse and redistribute offers under the reuse license, excluding contact data; this app has not obtained/confirmed that partner license or OAuth credentials, so the adapter remains disabled. The JobStream full sync timed out at 120 seconds before counts or field availability could be recorded. NAV has no configured local token. Therefore yield, sync request count/time, cross-source merge precision on 100 real reviewed pairs, deduplicated reach and India-relevant share remain **Unverified**. Exact-key grouping is covered by a 12-listing synthetic integration test for ATS-first canonical choice and the 10-variant bound; no fuzzy or vector-based merges occur.

The latest deterministic 300-title sample is stratified by source and predicted family and remains unlabeled: 35/300 predicted unclassified (11.67%). Current active catalog prediction counts are 74/618 unclassified (11.97%): Jobicy 55/511 (10.76%), Remote OK 16/99 (16.16%), Remotive 1/4 (25%), and mock rows 2/4 (50%).
